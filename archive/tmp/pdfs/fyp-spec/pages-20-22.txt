          2.7.1 Use Case Descriptions                                               
                                                                                    
                                                                                    
          Use Case 1: Student Registration                                          
                                                                                    
           Use Case       UC1: Student Registration                                 
           Primary Actor  Student                                                   
           Pre-Conditions Student is not registered in the system                   
           Post-Conditions Student account is created and stored in the database    
           Main Scenario  1. Student opens the system and selects “Register”.       
                          2. System displays registration form.                     
                          3. Student enters required details.                       
                          4. System validates the data.                             
                          5. System creates account and confirms registration.      
           Alternative    5a. If email already exists, system shows an error.       
           Scenario       5b. If required fields are missing, system asks student to complete the
                          form.                                                     
                                                                                    
          Table 2.1: UC1 – Student Registration                                     
                                                                                    
                                                                                    
          Use Case 2: Student Login                                                 
           Use Case        UC2: Student Login                                       
                                                                                    
           Primary Actor   Student                                                  
           Pre-Conditions  Student is registered                                    
           Post-Conditions Student is authenticated and redirected to home/chat screen
           Main Scenario   1. Student selects “Login”.                              
                           2. System displays login form.                           
                           3. Student enters credentials.                           
                           4. System validates credentials.                         
                           5. On success, system grants access.                     
           Alternative Scenario 4a. Invalid email/password results in an error message.
                           5a. Network/system issue results in login failure notice.
